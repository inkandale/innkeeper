# ink instances, plugins, and backups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ink instances`, `ink plugins`, and `ink backups` cover the admin routes that today need `ink call`.

**Architecture:** Client only; the API already has every route. Each namespace is a file in `cmd/ink` built from the existing helpers: `newClient`, `show` for tables and `--json`, `startJob` for routes that queue a job, and `parseID`. Two helpers are new: `confirm`, which asks before a step that can't be undone, and `client.send`, which sends a request whose body isn't JSON, for the restore upload.

**Tech Stack:** Go 1.27, `github.com/spf13/cobra`.

Ticket: INN-21, slice 21e. The slices are listed in `docs/superpowers/plans/2026-10-07-21a-ink-client.md`.

Decisions recorded during planning:

- `ink instances check <id>` reads the instance and exits non-zero if it's broken, printing the error. The API has no route that probes an instance, and `broken_error` is what it offers. A probe route is a server change for a later slice.
- Secrets never go on the command line, where they land in shell history and `ps`. `--secrets <file>` reads a JSON object from a file, or from stdin with `-`. For `configure`, a `null` value removes that secret, as the API does.
- `ink plugins install <name> [version]` reads `/plugin-catalog` to fill in what's missing: the newest version, and the source when only one offers the plugin. `--source` picks one when several do.
- `ink plugins purge` and `ink backups restore` ask before they run, since neither can be undone. `--yes` skips the question. Without `--yes` and with no terminal on stdin, they fail instead of waiting for an answer.
- `ink backups download <name> [file]` streams to `<name>.tar.gz` by default and deletes the file if the transfer breaks, so a truncated archive never looks whole.
- Response rows are local structs, as `job` and `source` are. `internal/wire` has no types for these routes, and moving `plugins.InstanceInfo` and the backup types there would change server packages for no client gain.

Not in this slice: deleting an instance asks nothing, as the web UI doesn't; its jobs stay.

## File structure

| File | Responsibility |
|---|---|
| `cmd/ink/confirm.go` | `confirm`: ask before an irreversible step, or refuse without a terminal |
| `cmd/ink/client.go` | `client.send`: a request with any body and content type |
| `cmd/ink/commands.go` | `jobStarted`, split out of `startJob` for the restore upload |
| `cmd/ink/instances.go` | `ink instances` |
| `cmd/ink/plugins.go` | `ink plugins`, `ink plugins catalog`, `install`, `remove`, `purge`, `sources` |
| `cmd/ink/backups.go` | `ink backups`, `create`, `download`, `restore` |
| `cmd/ink/main.go` | Registers the three namespaces |
| `README.md` | The new commands in the command list, and in place of `ink call` examples |

Tests use `stubAPI` and `runInk` from `cmd/ink/main_test.go`. No test needs the database.

### Task 2: `confirm`

**Files:**
- Create: `cmd/ink/confirm.go`, `cmd/ink/confirm_test.go`

- [ ] **Step 1: Write the failing test**

`TestConfirm` checks that `--yes` passes without reading, that a non-terminal stdin fails with a message naming `--yes`, and, with `stdinIsTerminal` replaced, that `y` passes and an empty line fails.

- [ ] **Step 2: Implement**

```go
// stdinIsTerminal reports whether r is a terminal; tests replace it.
var stdinIsTerminal = func(r io.Reader) bool {
	f, ok := r.(*os.File)
	if !ok {
		return false
	}
	fi, err := f.Stat()
	return err == nil && fi.Mode()&os.ModeCharDevice != 0
}
```

`confirm(cmd, yes, question)` returns nil for `yes`, an error naming `--yes` when stdin isn't a terminal, and otherwise asks on stderr and accepts `y` or `yes`.

**Files:**
- Create: `cmd/ink/backups.go`, `cmd/ink/backups_test.go`
- Modify: `cmd/ink/client.go`, `cmd/ink/commands.go`, `cmd/ink/main.go`

- [ ] **Step 1: Write the failing test**

`TestBackups` checks:

- `ink backups` prints `NAME TYPE STATUS CREATED SIZE ERROR`.
- `ink backups create assets` posts `{"type":"assets"}` and prints the job line; `create bogus` fails.
- `ink backups download b1 <file>` writes the archive; with no file it writes `b1.tar.gz` in the working directory.
- `ink backups restore <file> --replace --yes` posts a multipart body holding the archive and `replace=true`, and prints the job line; without `--yes` it fails and sends nothing.

`TestDownloadRemovesPartialFile` serves a body that breaks mid-transfer and checks the file is gone.

- [ ] **Step 2: Split `client.request`**

Move everything after building the request into `send(req *http.Request, path string) (*http.Response, error)`, which sets the token, sends, and turns an error status into an error. `request` builds a JSON request and calls it.

- [ ] **Step 3: Split `startJob`**

Move its `show` call into `jobStarted(cmd, out)`, which restore calls after its upload.

- [ ] **Step 4: Implement**

Restore streams the multipart body through an `io.Pipe`, so the archive isn't held in memory. Download streams to the file and removes it on error.

- [ ] **Step 5: Run the test, then commit**

Commit: `feat(ink): ink backups lists, creates, downloads, and restores backups`
