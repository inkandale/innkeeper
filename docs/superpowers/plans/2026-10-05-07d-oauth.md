# OAuth for MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let any MCP client, such as claude.ai on a phone, connect to `/mcp` through OAuth 2.1, with the owner choosing the tier it gets.

**Architecture:** Innkeeper acts as its own authorization server. Clients discover it from `/.well-known` documents, register themselves, and send the owner through `/oauth/authorize`. There the owner logs in with an existing login plugin, if needed, and approves a tier. The client exchanges the code, with PKCE, at `/oauth/token` for an access token and a refresh token. Access tokens work only on `/mcp`: the MCP layer marks its in-process API requests, and the API accepts an access token only on a marked request.

**Tech Stack:** Go 1.27, `html/template` for the two pages, the MCP SDK's `auth` and `oauthex` packages. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-05-mcp-server-design.md`, "Sign-in". Build order step 4.

**Kaneo:** INN-7.

## Design notes

- **Needs a public URL.** The issuer, the endpoints, and the resource are absolute URLs under `INNKEEPER_PUBLIC_URL`. Without it the OAuth routes return `404`, the `/.well-known` documents don't exist, and `/mcp` takes API tokens only.
- **Storage** (migration `0007_oauth.sql`). Every secret is stored as its SHA-256, like API tokens.
  - `oauth_client`: `id` (random, public), `name`, `redirect_uris`, `created_at`.
  - `oauth_code`: `hash`, `client_id`, `redirect_uri`, `challenge`, `tier`, `expires_at` (60 s), `used_at`.
  - `oauth_grant`: `id`, `client_id`, `tier`, `created_at`, `last_used_at`. Revoking a grant deletes it and, by cascade, its tokens.
  - `oauth_token`: `hash`, `grant_id`, `kind` (`access` or `refresh`), `expires_at`, `used_at` (refresh only).
- **Registration** (RFC 7591). `POST /oauth/register` takes `client_name` and `redirect_uris`. Each URI must be `https`, or `http` on `localhost`, `127.0.0.1`, or `[::1]`, and have no fragment. The reply has `client_id` and `token_endpoint_auth_method: "none"`. Registration grants nothing, but it is open, so clients that never got a grant are deleted after a day.
- **Authorize.** `GET /oauth/authorize` checks `response_type=code`, a known `client_id`, an exact registered `redirect_uri`, `code_challenge_method=S256`, a `code_challenge`, and `resource`, if sent, equal to `<public>/mcp`.
  - A bad `client_id` or `redirect_uri` gets an error page, never a redirect. Other errors redirect back with `error` and the client's `state`.
  - With no session, it shows the login page. Form providers render their fields. Redirect providers start their redirect, with a `return_to` cookie, so the provider's callback comes back to the authorize URL.
  - With a session, it shows the consent page: the client's name, the redirect host, and radio buttons for the three tiers with `read` checked.
- **Consent.** `POST /oauth/authorize` carries the original parameters, the tier, and a CSRF token: an HMAC of the session and the parameters, keyed by a per-process random key. It needs the session cookie and `Sec-Fetch-Site` of `same-origin` or absent. Approval redirects with `code` and `state`; denial redirects with `error=access_denied`.
- **Token.** `POST /oauth/token` takes form fields.
  - `authorization_code`: the code (unused, unexpired, for this client and `redirect_uri`) and a `code_verifier` whose S256 matches. A reused code revokes the grant it made. The reply has `access_token` (`inka_…`, 1 hour), `refresh_token` (`inkr_…`, 30 days), `token_type: "Bearer"`, `expires_in`, and `scope` (the tier).
  - `refresh_token`: replaces the refresh token and issues a new access token. A refresh token used twice revokes the whole grant.
- **Using tokens.** The `/mcp` verifier tries API tokens, then access tokens. It returns the grant's tier and the expiration, and the SDK checks the expiration. Tools mark their in-process requests with `auth.ViaMCP(ctx)`, a context value that no HTTP request can set. The API accepts an `inka_` token only on such a request. The 401 from `/mcp` names the resource metadata URL.
- **Discovery.** `/.well-known/oauth-protected-resource` and `/.well-known/oauth-protected-resource/mcp` describe the resource. `/.well-known/oauth-authorization-server` lists the endpoints, `S256`, `none`, both grant types, and the scopes `read`, `write`, `destructive`.
- **Grants in the token list.** `GET /grants` lists grants by client name, tier, and last use. `DELETE /grants/{id}` is `destructive`. `innkeeper token list` shows grants under the API tokens, and `innkeeper token revoke-grant <id>` revokes one.
