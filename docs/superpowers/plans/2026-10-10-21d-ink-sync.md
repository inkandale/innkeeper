# ink sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ink sync push` shows what it would replace in the app and asks first, and `ink sync` lists, checks, adopts, and unbinds bindings.

**Architecture:** Client only; the API already has every route. A card push reads `GET /cards/{id}/push-preview`, prints the changes, asks, and sends the preview's `confirm`, so the server refuses the push with `409` if the app's copy changed since. A query push searches with the `targets` facet and prints counts instead of diffs. The binding, push, change, and preview types move to `internal/wire`, as the reconcile types did in 21a, with aliases in `internal/targets` so server code is unchanged.

**Tech Stack:** Go 1.27, `github.com/spf13/cobra`.

Ticket: INN-21, slice 21d. The slices are listed in `docs/superpowers/plans/2026-10-07-21a-ink-client.md`.

Decisions recorded during planning:

- **No `ink sync bind`.** `ink sync resolve <instance-id> <remote-id> bind <card-id>` already binds an app item to a card, after a comparison, with a choice per hunk. `POST /cards/{id}/bind`, which accepts the app's copy as it is, stays reachable with `ink call`.
- **A card push asks only when it would change the app's copy:** when the preview `replaces` a copy and lists `changes`. A first push, a new copy, or a push to an in-sync copy goes ahead without asking. The preview prints to stderr, so `--json` output stays the job alone.
- **A query push prints counts, not diffs.** A diff per card means reading every card back from the app. `ink` searches with the `targets` facet, as the web's bulk push does, prints how many cards are new, ahead, in sync, drifted, missing, or can't be checked on that app, and asks once if any copy there would be replaced (bound and not missing). The counts come from the last check, and `POST /pushes` takes no `confirm`, so nothing guards them between the question and the push. `ink sync preview` shows one card's diff. A query that matches no cards is refused.
- **Without a terminal on stdin, a push that would ask is refused** unless `--yes` is given, so a script never hangs or replaces app content unasked. `ink sync unbind` asks the same way, since it deletes the push history.
- **`ink sync adopt` reads the card's head revision itself**, from `GET /cards/{id}` (or `/lorebooks/{id}`), and sends it as `base_revision_id`. Adopting writes a new library revision and loses nothing, so it doesn't ask.
- Binding commands take a binding ID, so they work for lorebook bindings too. Listing bindings takes a card ID; a lorebook's are at `ink call GET /lorebooks/{id}/bindings`. Lorebook pushes stay out of `ink sync push`, as before.
- Status runs `POST /bindings/{id}/check`, which reads the app now. `ink sync bindings show` prints the stored status without reading the app.
