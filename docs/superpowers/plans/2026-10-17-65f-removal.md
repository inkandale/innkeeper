# INN-65f: Removal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete catalog ingest, `catalog.similar`, adopt, catalog matches, and the Archive UI, now that archives are import plugins writing to a library.

**Architecture:** Build step 6 of the [libraries design](../specs/2026-10-16-libraries-design.md), its "Removed" table. Pass-through catalogs keep `catalog.describe`, `catalog.search`, and `catalog.get`, the routes `GET /catalogs`, `GET /catalogs/{id}/search`, and `GET /catalogs/{id}/items/{item}`, and `catalog:<id>` search sources, with their library matches (`MatchHashes`). `HashMatch` stays for **In other libraries**. A migration deletes `catalog.ingest` jobs, which no worker claims any more. The chart gains `persistence.blobs.enabled` for the homelab's NAS blob store.

**Tech Stack:** Go, PostgreSQL migrations, huma, React and TypeScript, Helm.

## Compatibility

A manifest declares capabilities, not methods, so a catalog plugin that still answers `catalog.ingest` loads as before. Its `catalog.describe` reply may still hold `ingest` and `similar`; Go's JSON decoding ignores unknown fields, so the reply still validates. A protocol test pins that.
