# INN-65c: Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-importing a source item updates its one card: nothing for content already stored, a new revision when the owner hasn't edited the card, and a pending source update when they have. Imports target a library, `emit.card` carries a version label, a date, and enrichment values, and a `bulk` plugin writes each checkpoint's cards in one transaction.

**Architecture:** Build step 3 of the [libraries design](../specs/2026-10-16-libraries-design.md). The record of what an import last sent for an item is an **import binding**: a pull-only binding (`push = false`, new column `imported = true`) on the importing instance, with `remote_id` set to the item's provenance (`<plugin>:<item>`, unchanged). Its `accepted_data` and `avatar_hash` are the copy last taken into the library; while the owner's edits block an update, `seen_data` and the new `seen_avatar` hold the waiting copy and `remote_state` is `changed`. That is the shape of a followed source from the [source updates design](../specs/2026-10-14-source-updates-design.md), so the changes queue, review, resolve, dismiss, and autosync work on it once targets reads an import binding's "upstream" copy from the row instead of calling the plugin, which can't answer `target.get`.

`library` writes import bindings itself, so an import is one transaction and a bulk checkpoint can hold a thousand of them. "The owner edited the card" means the head's content hash or avatar differs from the accepted copy's.

**Tech Stack:** Go, PostgreSQL, the fake plugin in `internal/fakeplugin`.

## Decisions

| Topic | Decision |
|---|---|
| Last imported copy | The import binding's `accepted_data` and `avatar_hash`, not a revision pointer: after a merge, the last accepted upstream copy matches no revision. |
| Provenance | Unchanged: `<plugin>:<item>`. Lookup is by `(library_id, provenance)`, newest card first, so cards duplicated by the old behavior keep working. |
| Legacy cards | A card imported before this change has no import binding. The first re-import creates one whose accepted copy is the newest revision written with the import's source, else the first revision. |
| url-import | Its instance also follows site sources, so an entity may have a followed binding and an import binding on one instance. The `(instance_id, card_id)` and `(instance_id, lorebook_id)` unique constraints gain `imported`. |
| Synthetic target | For an import binding, targets uses the stored copy as the app item, with every key of the stored and accepted copies as its fields, so nothing is projected away. |
| Source checks | Skip import bindings, except a changed one with autosync on, which the check applies without fetching. That catches an update recorded before autosync was turned on or before a crash. |
| Values | Checked against the manifest's `[enrichments]` with the rules `enrich.Check` uses, moved to `protocol.CheckValues`. A dropped key is a warning in the job's progress. Kept values are stored on the revision the import wrote, or on the head for a pending update; an import that changed nothing stores none. |
| `version`, `created` | The revision's `message` (default "Imported") and `created_at`. A pending update applied later gets resolve's message. |
| Bulk | Items are buffered until `checkpoint`, then stored and the checkpoint saved in one transaction, each item in a savepoint so a bad one fails alone. No source detection is queued. Leftovers are stored when `import.run` returns. |
| Library | The job payload's `library`, default `library.DefaultLibrary`. Nothing sets it until step 4. |
| Blobs | Garbage collection keeps a blob that a binding's `seen_avatar` names. |
