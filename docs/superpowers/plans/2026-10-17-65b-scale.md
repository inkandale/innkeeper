# INN-65b: Scale Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search, similar lookup, and facets stay fast on a 300k-card library and read only one library.

**Architecture:** Build step 2 of the [libraries design](../specs/2026-10-16-libraries-design.md).

- **Bands.** Migration 0030 adds an immutable SQL function `hash_bands(bigint)`: catalogkit's 9 bands of 7 bits, each tagged with its band number. Stored generated columns `text_bands` on both revision tables and `phash_bands` on `blob` call it, each with a GIN index. A generated column backfills existing rows when it is added and fills every later insert, so no Go writer changes and the revision immutability trigger never fires.
- **Similar lookup.** `SimilarCards` and `MatchHashes` share one SQL builder. It selects candidates by `&&` band overlap through the GIN indexes, keeps those within the exact distance, and keeps only head revisions of entities in the probe's library. Distances above 8 can miss matches, so both refuse them, and the API's `max_distance` maximum drops from 32 to 8.
- **Library.** `Query.Library` (internal, default `DefaultLibrary`) puts `c.library_id = $1` first in every search condition, so search, facets, family grouping, and `SearchIDs` read one library. `MatchHashes` takes a library; `SimilarCards` uses the card's own.
- **Keyset cursor.** Each sort is a list of key expressions plus `c.id`, all ascending or all descending. A hit's cursor is `jsonb_build_array(keys..., c.id)`, base64url-encoded; the next page adds a row comparison `(keys..., c.id) < (cursor values)`. Nullable keys (name, enrichment value) become a null flag plus a `coalesce`d value, so the comparison never meets a null. Family pages keep a family only if every one of its matches comes after the cursor, which is the same as its best match coming after. Page numbers stay offsets.
- **Facet cap.** Each facet count stops at 1,001, meaning more than 1,000, and the sidebar shows "1,000+".

The design puts the band function in `cardhash`. With generated columns only SQL computes bands, so a Go copy would be a second definition of the same rule with no caller; it stays in the migration.

**Tech Stack:** Go, PostgreSQL 18 (generated columns, GIN on `int[]`), huma, React.
