# INN-65a: Libraries Table Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every card and lorebook belongs to a library, and the API reports which.

**Architecture:** Build step 1 of the [libraries design](../specs/2026-10-16-libraries-design.md). A migration adds a `library` table holding library 1, "Library", and a `library_id` column on `card` and `lorebook` that defaults to 1, so existing rows and every current insert land in library 1 without touching the write paths. `library.Entity` and the API's entity output gain the ID. Creating, renaming, and deleting libraries, and writing to other libraries, come in later steps.

**Tech Stack:** Go, PostgreSQL migrations in `internal/db/migrations`, huma for the API, `npm run gen` for the web schema.

- [ ] **Step 3: Write the migration**

Create `internal/db/migrations/0029_library.sql`:

```sql
-- Every card and lorebook belongs to one library. Rows written without a
-- library go to library 1.
CREATE TABLE library (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name text NOT NULL UNIQUE CHECK (name <> ''),
    created_at timestamptz NOT NULL DEFAULT now()
);

INSERT INTO library (id, name) VALUES (1, 'Library');
SELECT setval(pg_get_serial_sequence('library', 'id'), 1);

ALTER TABLE card ADD COLUMN library_id bigint NOT NULL DEFAULT 1 REFERENCES library;
ALTER TABLE lorebook ADD COLUMN library_id bigint NOT NULL DEFAULT 1 REFERENCES library;
CREATE INDEX ON card (library_id);
CREATE INDEX ON lorebook (library_id);
```

`GENERATED BY DEFAULT` lets the migration insert ID 1; `setval` makes the next insert get 2. A constant default makes `ADD COLUMN` instant, with no table rewrite.
