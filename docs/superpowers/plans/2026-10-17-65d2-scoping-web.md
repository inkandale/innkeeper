# INN-65d2: Scoping Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner can switch between libraries in the web UI, fork a card into another library, see matches in other libraries, and create, rename, and delete libraries in Settings.

**Architecture:** The web half of build step 4 of the [libraries design](../specs/2026-10-16-libraries-design.md), on top of the [scoping API](2026-10-17-65d-scoping-api.md).

- **Current library.** `web/src/shell/library.ts` owns it: `useLibrary()` reads `?library=` from the URL; without one it falls back to the last library used, kept in localStorage, and then to 1. A library that `GET /libraries` no longer lists also falls back to 1. The switcher remembers the current library, and the rail links carry it. Card and lorebook pages put their entity's library in the URL with `useFollowLibrary`, so the switcher and rail follow the item being viewed.
- **Switcher.** A select at the top of the rail, in `Shell.tsx`, lists `GET /libraries`. Choosing one opens the same page (Cards, Lorebooks, Collections, Sync) in that library, or Cards from any other page, dropping filters that belong to the old library.
- **Library pages.** `CardQuery` gains `library`, so the search body, facets, bulk actions, and the URL carry it from one place. `collectionsQuery(library)`, `POST /cards`, `POST /collections`, `POST /imports`, `POST /source-checks`, Sync's target counts, and Review's "Other match" picker take the current library. The Cards selection and the import list reset when the library changes, so a bulk action never reaches a library the owner didn't pick it in. The card and lorebook pages use the entity's own `library_id` for their collections, variant picker, linked-item lookups, and Forge @-mentions.
- **Card and lorebook pages.** Show the library's name. **Fork into…** lists every library, forks into the chosen one, and shows why a fork failed. **In other libraries** replaces **Found in archives**, naming matches with one search per library; `web/src/archives/` stays until step 6.
- **Settings → Libraries.** Lists libraries with counts; create and rename inline, as Collections does. Delete asks for the exact name with `prompt`, as Plugins' "Remove data" does, sends it as `confirm`, and shows the job with `JobLine`. A mistyped name says nothing was deleted; refused requests show the API's reason. Library 1 has no delete.

**Tech Stack:** React, TypeScript, TanStack Query, React Router, vitest.

## Decisions

| Topic | Decision |
|---|---|
| No `?library=` | The last library used, else 1, so a link that drops the parameter stays in the library the owner was in. |
| Links | Rail links and links to filtered card lists carry `?library=`. Links to a card or lorebook don't need it: the page reads the entity's library. |
| Switching | Drops the list's filters: collection and target IDs belong to the old library. |
| Typed confirmation | `prompt`, the pattern Plugins already uses for a destructive action. |
