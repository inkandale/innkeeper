# Image and Helm Chart Plan

**Goal:** Run Innkeeper on Kubernetes: CI publishes the image to ghcr.io, and a Helm chart in this repo deploys it.

**Kaneo:** INN-16.

---

## Design notes

- **Image.** `.github/workflows/image.yml` builds the Dockerfile on every push to `main` and pushes `ghcr.io/davidgibbons/innkeeper:main` and `:sha-<commit>`. The plugins stage clones innkeeper-plugins with a read-only deploy key on that repo, stored here as the `PLUGINS_DEPLOY_KEY` secret. `PLUGINS_REF` moves to the plugins commit that has the list methods.
- **One pod.** The API and the worker share the blob store, so they run as two containers in one pod with one `ReadWriteOncePod` volume. One replica, `Recreate` strategy. Both migrate at startup; the migrator already holds an advisory lock.
- **Chart** at `chart/`. No OCI chart: a deployment reads it from git at a pinned commit. Add OCI publishing when someone outside this repo's readers needs it.
  - The database URL and the secrets key come from existing Secrets (`database.secretName`/`key`, `secretsKey.secretName`/`key`). The chart creates no Secrets.
  - Optional Ingress, the blob PVC, a Service on port 8080, `extraEnv`, pod annotations (for backup tools), and resources per container.
  - TCP probes on 8080; there's no health route.
  - Runs as UID 10001, the image's user, with `fsGroup` so the volume is writable.
- **CI** lints and renders the chart in `ci.yml`.
