# Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reconcile run applies the obvious decisions itself (bind exact matches, import new items) and owners see it as "Sync"; importing from an app and the `auto_bind_exact` setting go away.

**Architecture:** `ReconcileParams.Apply` picks `obvious` (default) or `none`. With `obvious`, the run's existing `autoBind` step becomes `autoApply`, which also resolves `new` items with `import` through `resolve`. Everything else is removals and renames across the API, MCP, `ink`, the web UI, and the README.

**Tech Stack:** Go, pgx, huma, cobra, React + TanStack Query, vitest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-09-sync-design.md`.

**Kaneo:** INN-40.

## Design notes

- **`Apply`** in `internal/wire/reconcile.go`:
  ```go
  // Apply is what a run resolves itself: ApplyObvious (the default) binds
  // exact matches and imports new items; ApplyNone writes nothing.
  Apply string `json:"apply,omitempty" enum:"obvious,none" required:"false"`
  ```
  with `const ApplyObvious, ApplyNone = "obvious", "none"`. Empty means `obvious`. `ReconcileItem` gains `AutoImported bool \`json:"auto_imported,omitempty"\``; `AutoBound`'s comment drops its mention of `auto_bind_exact`. Totals gain `auto_imported`, counted like `auto_bound` (each world book once).
- **`autoApply`** replaces `autoBind` in `internal/targets/reconcile.go`, and runs when `p.Apply != wire.ApplyNone` instead of when `named.AutoBindExact`. It drops the `GetInstance` call that read the setting.
  - An item is applied when its verdict is `exact` with a suggested `bind` (as today), or `new` with a suggested `import`, and every linked world book has a resolution from `autoNested`.
  - `autoNested` gains a case: a `new` world book with a suggested `import` gets `Action: "import"`, no `CardID`, no `BaseRevisionID`.
  - After a resolve, a world book the run imported is recorded in `nested` as `Action: "bind"`, `CardID: lr.CardID`, `BaseRevisionID: lr.RevisionID`, and its `accepted_hash`, so the next card that links it binds the new lorebook rather than importing it twice. `books.byID` doesn't hold the new lorebook, which is why `BaseRevisionID` comes from the result.
  - Mark `AutoImported` on items and world books whose resolution was `import`, `AutoBound` on those whose was `bind`.
  - Lorebooks first (`snap.Lorebooks`, `lorebookKind`), then characters, as today.
- **`resolveOpts.importNew`.** `autoApply` resolves with `resolveOpts{bindOnly: true, importNew: true}`. `bindOnly` still refuses any write to an existing library item (`resolve.go:588`); `importNew` lets `import` through the check at `resolve.go:167`. Manual bind (`bind.go:112`) keeps `importNew` false. If an import's own bind step trips `errWouldRevise`, the import's choices (`ChooseKeepInApp`, nil choices) are producing a revision: fix by skipping the `revise` check for the item an import just created, and say so in a comment.
- **Read-only tests.** Default `obvious` means `Reconcile` in existing tests now writes. Tests that assert nothing was written (`bindingCount() == 0`, verdict tables that a later step depends on) pass `Apply: wire.ApplyNone`. Don't change a test's expectations to fit the new writes; add `ApplyNone` instead.
- **Removed import.** `internal/targets/import.go` and `import_test.go` go. `appCard` and `pngFile` in `import_test.go` are used by other tests; move them to `env_test.go` first. `POST /imports` on an instance without `import` returns `400` "plugin X has no importer; sync the app with POST /reconciles".
- **Migration** `internal/db/migrations/0016_drop_auto_bind_exact.sql`: `ALTER TABLE plugin_instance DROP COLUMN auto_bind_exact;`.
- **Tier.** `start-reconcile` needs `tier.Write`. MCP `start_sync` is `tier.Write`.
- **Web schema.** After API changes, run `cd web && npm run gen` to regenerate `openapi.json` and `src/api/schema.d.ts`; commit them with the API change.
